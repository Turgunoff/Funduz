# Жизненный цикл проекта

## Статусы

```
   draft
     │
     ▼
  pending_review ──── rejected (финальный)
     │
     ▼
   active ──────► failed ───► refunded (финальный)
     │
     ▼
   funded ───► in_delivery ───► completed (финальный)
```

| Статус | Описание |
|---|---|
| `draft` | Автор создаёт проект, ещё не отправлен |
| `pending_review` | Отправлен на модерацию, админ проверяет |
| `rejected` | Админ отклонил (с причиной) |
| `active` | Одобрен и открыт, бэкеры могут делать pledge |
| `funded` | Deadline прошёл, цель достигнута |
| `failed` | Deadline прошёл, цель не достигнута |
| `refunded` | Все возвраты бэкерам отправлены |
| `in_delivery` | Автор доставляет награды |
| `completed` | Все награды доставлены, проект закрыт |

---

## Детализация по этапам

### 1. Draft
- **Кто:** Автор проекта
- **Действия:** заполнение wizard, сохранение черновика, теги, изображения
- **Проверки:** обязательные поля, размеры изображений, формат видео URL
- **Notification:** нет

### 2. Pending review
- **Кто:** Автор → админ
- **Действия:**
  - Автор нажимает "Отправить на модерацию"
  - В admin panel появляется новый проект
  - Админ проверяет: контент, юридический аспект, отчётность, реальность
- **Время:** максимум 48 часов
- **Notification:**
  - Автору: "На модерации"
  - Админу: новая review queue (in-app + Telegram)

### 3. Active (live)
- **Кто:** Бэкеры
- **Действия:**
  - Просмотр, share проекта
  - Создание pledge (выбор награды + оплата)
  - Чтение обновлений
  - Комментарии (v1.1+)
- **Проверки:**
  - Автор **не может редактировать** проект (только добавлять updates)
  - Если запас награды (limit) исчерпан — нельзя выбрать
- **Notification:**
  - Автору: новый pledge, дневной summary
  - Бэкерам: обновления проекта

### 4a. Funded
- **Trigger:** deadline + total_pledged >= goal
- **Автоматические действия:**
  - Cron job проверяет проекты
  - `project.status = 'funded'`
  - Для каждого pledge: `payment.confirm()`
  - Считается комиссия (7%)
  - Зачисление на баланс автора (UZS)
- **Notification:**
  - Автору: "Поздравляем! Ваш проект funded"
  - Бэкерам: "Проект успешно завершён"

### 4b. Failed
- **Trigger:** deadline + total_pledged < goal
- **Автоматические действия:**
  - `project.status = 'failed'`
  - Для каждого pledge: `payment.cancel()` (refund)
  - Комиссия не взимается
- **Notification:**
  - Автору: "К сожалению, цель не достигнута"
  - Бэкерам: "Возврат отправлен"

### 5. In delivery
- **Кто:** Автор проекта
- **Действия:**
  - Доставка наград
  - Обновления о доставке
  - Личные сообщения бэкерам (адрес, tracking)
- **Время:** дедлайн установлен автором (обычно 1–6 месяцев)
- **Проверка:** админ отслеживает жалобы

### 6. Completed
- **Trigger:** автор отмечает "Доставлено"
- **Или:** прошло 6 месяцев и нет жалоб
- **Notification:**
  - Бэкерам: запрос feedback

## Особые случаи

### Отмена проекта (автором, во время active)
- Нужно разрешение админа
- Все pledges возвращаются
- Статус `cancelled` (дополнительный)

### Жалоба (dispute)
- Бэкер нажимает "Жалоба" (in_delivery или completed)
- Админ проверяет
- Решение: refund или отказ
- Feature v1.1+

### Cheating detection
- Автор backing своего же проекта (self-pledging)
- Отлавливается по IP, устройству, номеру телефона
- Admin alert + audit log

## Cron jobs (BullMQ)

| Job | Периодичность | Назначение |
|---|---|---|
| `check-project-deadlines` | каждые 5 минут | Решение funded/failed |
| `auto-refund-failed` | каждые 10 минут | Возврат failed проектов |
| `notification-digest` | раз в день | Summary email авторам |
| `cleanup-drafts` | раз в неделю | Удаление 90-дневных нетронутых черновиков |
| `analytics-rollup` | каждый час | Подсчёт статистики (для homepage) |
