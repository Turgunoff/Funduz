# Дорожная карта по настройке и развертыванию бэкенда (Backend & Deployment Roadmap)

## I. Подключение к серверу и настройка безопасного доступа

- [x] 1. Создать личный SSH-ключ (пару ключей) на своем компьютере.
- [x] 2. Скопировать открытую часть ключа (public key) и разместить её на купленном сервере.
- [x] 3. Подключиться к серверу через терминал своего компьютера без пароля, по безопасному соединению.
- [x] 4. Создать внутри сервера еще один SSH-ключ для связи с GitHub и добавить его в свой GitHub-аккаунт.

## II. Настройка базы данных

- [ ] 5. Создать внутри PostgreSQL новую пустую базу данных и специального пользователя для проекта (с логином и паролем).

## III. Загрузка проекта и подготовка рабочего окружения

- [ ] 6. Создать на сервере специальную папку, где будет храниться ваш проект.
- [ ] 7. Скачать (клонировать) код фронтенда и бэкенда из GitHub в эту папку.
- [ ] 8. Создать и заполнить файлы `.env` (с паролями от базы данных, ключами и настройками) внутри папок бэкенда и фронтенда.
- [ ] 9. Установить все необходимые внешние библиотеки и пакеты для работы бэкенда и фронтенда (командой `npm install` или аналогичной).

## IV. Запуск проекта на сервере

- [ ] 10. Запустить команду применения миграций для создания таблиц в базе данных.
- [ ] 11. Запустить бэкенд-проект в фоновом режиме с помощью PM2, чтобы он работал непрерывно.
- [ ] 12. Собрать фронтенд-проект в готовый для публикации вид (выполнить build).

## V. Настройка домена, сети (Nginx) и SSL

- [ ] 13. Направить купленный домен (например, saytim.uz) на IP-адрес вашего сервера в настройках домена.
- [ ] 14. Написать правило для Nginx: "если люди заходят на домен — показывать им фронтенд, а если обращаются к `/api` — перенаправлять запрос на бэкенд".
- [ ] 15. Установить бесплатный SSL-сертификат (HTTPS — зеленый замочек) для вашего домена.

## VI. Настройка CI/CD через GitHub Actions (Автоматизация)

- [ ] 16. Зайти в настройки репозитория на GitHub и надежно сохранить там IP-адрес сервера и ключи подключения (в разделе Secrets).
- [ ] 17. Создать внутри вашего проекта специальный файл инструкций для GitHub Actions.
- [ ] 18. Написать код автодеплоя, чтобы при отправке изменений в GitHub (push) сервер сам скачивал новый код, перезапускал бэкенд и заново собирал (build) фронтенд.
